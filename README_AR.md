# رُكن — Rukn Expiry 2.0 (نسخة إعادة البناء التجريبية)

## ماذا تحتوي الحزمة؟

مشروع Android Kotlin جديد منفصل عن التطبيق السابق حتى لا يكتب فوق بياناته. الاسم الظاهر للمستخدم **رُكن | إدارة الصلاحية**، ومعرّف التطبيق `com.rukn.expiry.rebuilt`. يمكن تثبيت النسختين جنبًا إلى جنب.

- واجهة عربية RTL: لوحة مؤشرات، حالات انتهاء الصلاحية، سجل المنتجات، المساعد، والإعدادات.
- حفظ المنتجات محليًا في SQLite دون حساب، مع التعديل وإضافة الباركود والتواريخ والكمية والوصف والموقع.
- تعرف على الأوامر العربية عبر `SpeechRecognizer` المدمج في أندرويد، مع تفضيل التعرف على الجهاز إن توفر، ومجموعة تفضيلات للهجات العربية (`ar-YE`, `ar-SA`, `ar-EG`, `ar`). لا يحتاج المستخدم إلى كتابة أي عنوان خادم.
- دعم ردود منطوقة عربية عند الحفظ إذا كان صوت العربية مثبتًا في أندرويد.
- مراجعة الأوامر قبل تعديل المنتج، مع رفض التواريخ المستحيلة ومنع الكميات السالبة.
- مسح الباركود من Google Code Scanner عبر Google Play services، مع خيار الإدخال اليدوي إذا تعذّر المسح.
- جلب بيانات المنتجات الغذائية العامة بواسطة Open Food Facts عند الطلب (لا يُخمن تاريخ انتهاء السلعة من الباركود).
- استيراد CSV، XLSX متعدد الأوراق، وملفات SQLite محلية: تحليل العناوين العربية والإنجليزية، معاينة قبل الحفظ، تجاهل القيم غير الواضحة. حد الملف 20 ميغابايت وحد المعالجة 5000 صف.
- إذا تم تجهيز بوابة ذكاء سحابي وفعّلت مشاركة *رؤوس الأعمدة فقط* في الإعدادات، يحاول النظام استخدامها لتفسير الأعمدة غير المعروفة؛ لا يرسل صفوف المنتجات.
- تصدير بيانات المنتجات إلى CSV متوافق مع Excel للنسخ الاحتياطية.
- خادم Node.js اختياري لزيادة فهم الأوامر باللهجات عن طريق Gemini أو Groq أو OpenRouter؛ يتراجع التطبيق تلقائيًا إلى المعالجة المحلية إذا لم يُجهّز الخادم أو فشل.

## من أين أبدأ؟

### الطريقة الأسهل: GitHub Actions

1. أنشئ مستودعًا جديدًا على GitHub باسم `RuknExpiry2` أو استخدم فرعًا جديدًا؛ **لا تستبدل ملفات المشروع القديم قبل أخذ نسخة احتياطية**.
2. ارفع **محتويات** هذا المجلد إلى جذر المستودع مع المجلدات المخفية `.github` وملفات Gradle.
3. اذهب إلى تبويب `Actions` ثم `Rukn Expiry Android CI`. التشغيل عند رفع الملفات يبدأ تلقائيًا؛ أو استخدم `Run workflow`.
4. إذا نجحت `:core:test` و`:app:assembleDebug`، نزّل الأثر `RuknExpiry-debug-APK` من تبويب تشغيل Actions.
5. ثبت APK على هاتف أندرويد (Android 8.0 أو أحدث)، وامنح إذن الميكروفون عند الطلب.

الملف `android.yml` يستخدم JDK 17 وGradle 8.10.2 و`android-actions/setup-android@v4` وAndroid SDK 35، ويتوقف عند فشل الاختبارات بدلاً من تخطيها.

### Android Studio

افتح مجلد المشروع من Android Studio حديث يدعم AGP 8.7.3، وثبت JDK 17 وAndroid SDK 35. المشروع يستخدم Gradle 8.10.2. إن طلب البرنامج Gradle Wrapper، يمكن توليده في بيئة تحتوي على Gradle 8.10.2 بواسطة:

```sh
gradle wrapper --gradle-version 8.10.2
```

لا تتضمن هذه الحزمة Gradle Wrapper JAR جاهزًا؛ لذلك رفع المشروع إلى GitHub Actions أعلاه هو المسار المباشر للبناء.

## الصوت — دون إدخال روابط خوادم

1. افتح «المساعد» واضغط «ابدأ التحدث الآن» ثم اسمح بالميكروفون.
2. قل مثلًا: «تاريخ الانتهاء 2027-12-30 والكمية 15 حبة» أو افتح منتجًا موجودًا وقل: «غير سنة الانتهاء إلى 2027».
3. راجع التحليل والبيانات ثم اضغط حفظ. لا يُحفظ أي أمر تلقائيًا.
4. إذا لم تتوفر خدمة تعرف في الجهاز، ثبّت أو فعّل خدمة التعرف على الكلام المناسبة لنظامك، وقد تحتاج تنزيل حزمة اللغة العربية. الوضع دون إنترنت ليس مضمونًا على جميع الهواتف؛ يعتمد على الخدمة التي يوفرها النظام.

**مهم:** `SpeechRecognizer` نظام للتعرف على الكلام وتحويله إلى نص، وليس نموذج ذكاء اصطناعي سحابيًا. محرك `VoiceCommandEngine` يحوّل النص إلى حقول بشكل محافظ. عند وجود بوابة سحابية، تستخدم فقط إذا فشل المحرك المحلي في فهم النص.

## إثراء المنتجات بالباركود

يتطلب الإنترنت وخدمة Google Play services لمسح الكاميرا بالاعتماد على Google Code Scanner؛ إذا لم توجد، تستطيع كتابة الرقم. بيانات Open Food Facts قد تكون غائبة أو غير مكتملة، ولا تتضمن تاريخ انتهاء العلبة الفردية عادة. **لا تعتمد على نتيجة الكتالوج العامة للتحقق من سلامة الأغذية أو صلاحيتها.**

## الاستيراد الذكي

- المبدأ: استيراد موثوق قبل الذكاء التخميني. يبحث أولًا عن أسماء الحقول المعروفة، مثل «اسم المنتج»، «الباركود»، «الصلاحية»، «الكمية»، `Product Name`, `EAN`, `Expiry`, `Qty`, `Description`.
- صيغة تاريخ مدعومة: `YYYY-MM-DD`, `YYYY-MM`, `DD/MM/YYYY`. التاريخ غير الواضح يبقى كما ورد ويحصل على تحذير، ولا يُحفظ إذا كان غير صالح.
- يمكن قراءة XLSX وCSV وSQLite المحلية. ملفات Excel القديمة **`.xls`** والتوصيلات المباشرة إلى MySQL وSQL Server وERP غير مدعومة في هذا الإصدار. حوّل `.xls` إلى `.xlsx` أو `.csv`. لم يُصمّم أي مستورد يمكنه تفسير كل الجداول المجهولة بشكل مضمون؛ الصفوف غير المفهومة تحتاج مراجعة.
- الحفظ يدمج السجلات ذات الباركود المطابق فقط، ولا يدمج تلقائيًا حسب تشابه الأسماء.
- استورد عينة صغيرة أولًا، وراجع الحقول قبل إدخال بيانات المخزون الفعلية.

## تفعيل خدمات AI سحابية — اختياري للمسؤول فقط

**التطبيق يعمل دون هذه الخطوة**. إذا أردت فهمًا سحابيًا أوسع للهجات أو تخمين أسماء الأعمدة غير المعتادة:

1. أنشئ مفتاح API لدى واحد أو أكثر من: [Google AI Studio](https://aistudio.google.com/apikey)، [OpenRouter](https://openrouter.ai/keys)، أو [Groq](https://console.groq.com/keys). تتغير الحصص والإتاحة وفق الدولة والحساب والمزوّد، ولا توجد خدمة مجانية عامة غير محدودة يمكن تضمين مفتاحها للجميع.
2. انشر مجلد `server/` على استضافة Node.js تدعم Node 20 أو أحدث، بخدمة HTTPS عامة. أمر التشغيل: `node voice-server.mjs`، واختبر `GET https://YOUR-SERVER/health`.
3. ضع مفاتيحك في **متغيرات بيئة خادمك فقط**: `GEMINI_API_KEY`, `GROQ_API_KEY`, `OPENROUTER_API_KEY`. يجرّب الخادم Gemini ثم Groq ثم OpenRouter (يمكن تعديل النماذج عبر `GEMINI_MODEL`, `GROQ_MODEL`, `OPENROUTER_MODEL`). النماذج الافتراضية وقت إعداد هذه الحزمة: `gemini-3.5-flash-lite`, `openai/gpt-oss-20b`, `openrouter/free`.
4. في GitHub Repository > Settings > Secrets and variables > Actions > **Variables**، أنشئ متغير `RUKN_AI_BASE_URL` وضع فيه عنوان HTTPS النهائي لخادمك فقط، دون شرطة مائلة أخيرة. ثم أعد تشغيل Actions لبناء نسخة تدعم تحسين الأوامر الصوتية.
5. في التطبيق، من «الإعدادات» يمكنك *اختياريًا* السماح بإرسال **عناوين أعمدة** الملفات إلى الخادم لتحسين الاستيراد.

**الأمان:** لا تضع مفاتيح API داخل ملفات Android أو GitHub. البوابة البرمجية المرفقة **نموذج أولي وليست جاهزة للنشر المفتوح**: تحتوي على تحديد طلبات لكل IP ولكنها لا تملك هوية مستخدم أو تحقق Play Integrity أو حماية احترافية من الاستهلاك. لا تشغّلها لخدمة جمهور واسع قبل إضافة حماية حقيقية للمستخدمين، حدود مالية، مراقبة وقيود وصول. لن يضمن مطوّر موثوق أن الخدمات المجانية تعمل دائمًا دون إعداد أو قيود.

## خطة اختبار قبل توزيع التطبيق

1. `gradle :core:test` ثم `gradle :app:assembleDebug` على GitHub.
2. اختبار الصوت على هاتف يدعم خدمة التعرف بالعربية (يمني وخليجي ومصري)، وعلى هاتف غير متصل بالإنترنت إن كانت الحزمة المثبتة تدعم ذلك.
3. صلاحيات الميكروفون مرفوضة، والنقر المتكرر على التسجيل، وإغلاق نافذة الاستماع.
4. اختبار سنة كبيسة: 2028-02-29 -> 2027 يجب أن تُرفض؛ 2028-02-29 -> 2032 يجب أن يُقبل.
5. اختبار الماسح مع Google Play services، ومع جهاز لا يملك Play services.
6. البحث عن باركود موجود وغير موجود، والتحقق من استهلاك الشبكة ورسالة الخطأ.
7. استيراد CSV عربي، XLSX متعدد الأوراق، SQLite، ملف تالف، ملف أكبر من 20MB، وملفات بتاريخ غير صالح؛ لا تُخزّن البيانات دون مراجعة.
8. اختبار النسخة الاحتياطية والتراجع إلى ملف CSV للتأكد من عدم ضياع البيانات.
9. مراجعة قابلية الاستخدام لمستخدمي أندرويد، والألوان، وتكبير الخط، وقرّاء الشاشة، وأجهزة الشاشات الصغيرة.
10. بعد نشر الخادم، اختبار عدم الوصول غير المصرح به، والحدود المالية للـ APIs، واللاتينية/اللهجات العربية، والسرية وحماية البيانات.

## قيود التحقق لهذا التسليم

تم فحص تركيب خادم Node.js، وتجربة استجابته المحلية الصحية وفشل الخدمة دون مفاتيح، وتشغيل اختبارات مستقلة باستخدام مترجم Kotlin لمحرك الأوامر واستخراج بيانات CSV. **لم يُنشأ APK داخل بيئة التسليم** بسبب عدم توفر Android SDK/Gradle ولا هاتف أندرويد، ولم يتم اختبار Open Food Facts أو خدمات AI مباشرة بمفاتيح أو أجهزة. فحص GitHub Actions وتشغيل الاختبارات وAPK على جهاز حقيقي شرط قبل اعتماد التطبيق في العمل.
